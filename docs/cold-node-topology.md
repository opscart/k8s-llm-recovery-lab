# Cold-Node Recovery Topology

## Goal

Measure LLM functional recovery after Kubernetes moves the Ollama workload from one Azure VM-backed node to a separate Azure VM-backed node.

This experiment must not mix cold-node recovery with cold model acquisition.

## Target Topology

```text
Azure VNet / same region

k8s-llm-cpu-01
  kubeadm control plane
  schedulable
  research role: source
        |
        | Kubernetes cluster
        |
k8s-llm-cpu-02
  kubeadm worker
  research role: target
```

Both VMs should use the same:

- Azure region
- VM size
- Ubuntu release
- Kubernetes version
- container runtime
- Ollama image/version
- workload CPU/memory envelope

## Experiment Boundary

Before T0:

### Node A

- Ollama pod is running on Node A.
- `llama3.2:3b` artifact is present.
- A successful preconditioning inference has completed.
- `ollama ps` confirms the model is resident.

### Node B

- Node B is a different Azure VM.
- Node B is Kubernetes `Ready`.
- The required model artifact is already available to the replacement workload.
- The model is not resident.
- Node B has not yet served the measured workload.

The first experiment therefore excludes model download/acquisition from the recovery interval.

## Why This Is One-Shot

After Node B has served the model, it is no longer a first-use target under the same conditions.

The initial A -> B measurement should therefore be preserved as a one-shot cold-node observation.

Repeated trials require an explicit reset strategy, such as fresh target VMs or another defensible method that restores the intended target-node state.

## Cluster Preparation

On Node A:

```bash
sudo CNI_MANIFEST=/path/to/reviewed-pinned-cni.yaml \
  scripts/cloud/prepare-kubeadm-control-plane.sh
```

The script writes a temporary join command to:

```text
/tmp/kubeadm-join-command.sh
```

Do not commit this file or its token.

On Node B:

```bash
sudo scripts/cloud/prepare-kubeadm-worker.sh
```

Then run the secure join command generated by Node A.

After Node B joins, label it from Node A:

```bash
kubectl label node k8s-llm-cpu-02 llm-recovery-role=target --overwrite
```

Verify:

```bash
kubectl get nodes -o wide
kubectl get pods -A
kubectl get nodes --show-labels
```

## CNI

The preparation scripts intentionally do not hard-code an unreviewed floating CNI manifest.

Use a pinned CNI manifest compatible with:

```text
Pod CIDR: 10.244.0.0/16
Kubernetes: 1.35.1
```

Record the exact CNI name, version, and manifest source in the environment evidence.

## Azure Networking

The two VMs should be placed in the same VNet/subnet when practical.

The cluster requires node-to-node communication, including:

- Kubernetes API server TCP 6443 from Node B to Node A
- kubelet communication
- CNI-specific node-to-node traffic

Validate the actual NSG rules and CNI requirements before cluster creation.

Do not expose the Kubernetes API server broadly to the public Internet for this experiment.

## Artifact Placement

Artifact placement is deliberately handled separately from cluster bootstrap.

Before executing the cold-node recovery script, the model artifact must be available to the replacement workload on Node B without downloading it during T0-T4.

The exact mechanism must be documented because it changes the interpretation of the experiment.

Candidate approaches include:

- pre-staged node-local model data on both VMs,
- reviewed shared storage that is mounted by the workload.

Do not use a mechanism that silently adds model acquisition to the cold-node measurement.

## Evidence To Capture

Before the experiment:

```text
kubectl get nodes -o wide
kubectl get pod -n llm-recovery-lab -l app=ollama -o wide
kubectl get pv,pvc -n llm-recovery-lab
kubectl describe node k8s-llm-cpu-01
kubectl describe node k8s-llm-cpu-02
```

Record:

- VM SKU
- VM region
- OS version
- kernel version
- Kubernetes version
- containerd version
- CNI/version
- source/target node names
- storage/artifact-placement method

## Measurement

Use:

```text
scripts/recovery/ollama-llama32-3b-cloud-cold-node-recovery.sh
```

Required environment variables:

```bash
SOURCE_NODE=k8s-llm-cpu-01
TARGET_NODE=k8s-llm-cpu-02
```

The script verifies that:

- source and target differ,
- both nodes are Ready,
- the current Ollama pod is on the source,
- source inference succeeds before T0,
- the source model is resident before T0,
- the source is cordoned before pod deletion,
- the replacement lands on the target,
- the target model artifact exists before first inference,
- T0-T4 and Ollama timing fields are captured.

If the artifact is absent on Node B, the script aborts rather than contaminating the cold-node experiment with cold model acquisition.
